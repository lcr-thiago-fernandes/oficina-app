# Linguagem Ubíqua

Termos compartilhados entre código, documentação, conversas com o domínio e o vídeo de apresentação. Cada termo aparece **com o mesmo nome** no código (em português) e nos artefatos.

## Termos transversais

| Termo | Definição | Contexto principal |
|---|---|---|
| **Cliente** | Pessoa física ou jurídica dona de um veículo que solicita serviços | Gestão de Clientes |
| **Veículo** | Bem do cliente identificado por placa, marca, modelo e ano | Gestão de Clientes |
| **Documento** | CPF (PF, 11 dígitos) ou CNPJ (PJ, 14 dígitos) com dígitos verificadores válidos | Gestão de Clientes |
| **Placa** | Identificador único do veículo nos formatos antigo (`AAA9999`) ou Mercosul (`AAA9A99`) | Gestão de Clientes |
| **Serviço** | Operação ofertada pela oficina (ex: "Troca de óleo") com preço base e tempo estimado | Catálogo |
| **Peça** | Insumo físico identificado por SKU, com preço unitário e saldo de estoque | Estoque |
| **SKU** | Código alfanumérico único da peça | Estoque |
| **Movimentação de Estoque** | Registro de entrada ou saída de uma peça com motivo, data e (opcionalmente) OS associada | Estoque |
| **Saldo** | Quantidade atual disponível de uma peça (denormalizado, atualizado a cada movimentação) | Estoque |
| **Ordem de Serviço (OS)** | Documento que registra um atendimento da entrada à entrega do veículo | Ordem de Serviço |
| **Número da OS** | Identificador humano-amigável da OS (sequencial, ex: `#2026000123`) | Ordem de Serviço |
| **Item de Serviço** | Linha da OS referenciando um serviço, com nome e preço **snapshot** (preservados) | Ordem de Serviço |
| **Item de Peça** | Linha da OS referenciando uma peça, com nome e preço **snapshot** | Ordem de Serviço |
| **Snapshot** | Cópia do nome/preço no momento da inclusão no item; alterações no catálogo não afetam OS já criadas | Ordem de Serviço |
| **Orçamento** | Valor total da OS (soma dos itens) calculado em tempo real | Ordem de Serviço |

## Estados da OS

| Status | Descrição | Transição válida a partir de... |
|---|---|---|
| **Recebida** | OS criada; veículo registrado, sem diagnóstico | (estado inicial) |
| **Em Diagnóstico** | Mecânico avalia o veículo e adiciona itens | Recebida |
| **Aguardando Aprovação** | Orçamento enviado ao cliente | Em Diagnóstico (com pelo menos 1 item) |
| **Em Execução** | Cliente aprovou; serviço sendo realizado; estoque baixado | Aguardando Aprovação (com `OrcamentoAprovadoEm` preenchido) |
| **Finalizada** | Execução concluída; aguardando retirada | Em Execução |
| **Entregue** | Cliente retirou o veículo | Finalizada |
| **Cancelada** | Cliente rejeitou o orçamento | Aguardando Aprovação (rejeição) |

## Ações de processo

| Ação | Quem realiza | Efeito |
|---|---|---|
| **Diagnosticar** | Atendente/Mecânico | Recebida → Em Diagnóstico |
| **Adicionar item** | Atendente/Mecânico | Inclui serviço/peça com snapshot (apenas em estados editáveis) |
| **Enviar para aprovação** | Atendente | Em Diagnóstico → Aguardando Aprovação |
| **Aprovar orçamento** | **Cliente** (rota pública) | Marca `OrcamentoAprovadoEm` |
| **Rejeitar orçamento** | **Cliente** (rota pública) | Aguardando Aprovação → Cancelada |
| **Iniciar execução** | Atendente | Aguardando Aprovação → Em Execução; **baixa estoque** das peças |
| **Finalizar** | Mecânico | Em Execução → Finalizada |
| **Entregar** | Atendente | Finalizada → Entregue |

## Conceitos de Domínio

- **Agregado**: cluster de entidades tratado como unidade transacional; só uma raiz é mutável de fora.
- **Raiz do agregado**: entidade que controla as invariantes e expõe métodos de mutação.
- **Bounded Context**: limite de aplicabilidade de uma linguagem ubíqua. O sistema tem 4: Gestão de Clientes, Catálogo, Estoque, Ordem de Serviço.
- **Domain Event**: fato relevante já ocorrido (`ExecucaoIniciada`, `OrdemDeServicoFinalizada`, etc.).
- **Value Object (VO)**: objeto sem identidade, comparado por valor (ex: `Documento`, `Placa`, `SKU`).
